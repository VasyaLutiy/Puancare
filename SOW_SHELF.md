# ТЗ: сундук → шкаф (полка форм) + подготовка к запуску станка

*15 июля 2026. Рамка — насечка Кирилла: этап УПАКОВКИ. Проверяем точность
цикла «прожил → упаковал форму → узнал → переиспользовал карту». Извлечение
смыслов из форм и области их применения — ВНЕ рамки этого ТЗ.*

---

## 1. Зачем

Станок (worldforge) начнёт кормить организм потоком слепых миров-троек.
Сейчас накопленные формы живут в двух неподходящих местах:

- **сундук** (`chest.py`) — снимок ОДНОЙ полной жизни (records + hist +
  оси): для потока это гроб — тащит сырьё, которое после выжимки не нужно;
- **репертуар** — dict в памяти процесса (`fastpath`, `repertoire.py`),
  умирает со смертью процесса, не версионируется.

Нужен **шкаф**: постоянное хранилище компактных карточек форм, с версией,
от которой зависят пороги узнавания.

## 2. Термины

| термин | что это |
|---|---|
| карточка | выжимка одной ОТКРЫТОЙ формы: ось + подпись + карта использования |
| полка / шкаф | файл-библиотека карточек с монотонной версией |
| версия полки | целое, +1 на каждое добавление карточки; вердикты штампуются ею |
| ведомость | машиночитаемый журнал вердиктов экзаменов (JSONL) |

## 3. Что уже есть (переиспользовать, не переписывать)

- `chest.py` — JSON-кодек оси (`enc`/`dec`, `_AXIS_FIELDS`) готов, брать
  как есть. Сам chest.py НЕ удалять и не менять: «одна жизнь целиком» —

## 4. Карточка формы — формат

JSON-объект (кодеком chest), поля:

```
{
  "id":        "f0007",              # порядковый, выдаёт шкаф
  "added_v":   7,                    # версия полки, в которой появилась
  "origin":    "worldforge/out/exam/m03",   # откуда прожита (донор)
  "discovery": {"budget": 1500, "seed": 0}, # чем открыта (воспроизводимость)
  "axis":      {__axis__: ...},      # параметры оси (поля _AXIS_FIELDS
                                     #  из chest; БЕЗ records/hist!)
  "sig":       {...},                # koopman.signature(axis) — полная
  "sig_lens":  {"<действие>": {...}, ...},   # подпись через линзу каждого
                                     # действия оси (см. D1)
  "usemap":    {"<действие-использования>":  # эпизоды донора с class-метками,
                [[ctx, action, outcome, m], ...]},  # только use-действия —
                                     # ровно то, что ест import_usemap
  "k":         3,
  "roles":     [2, 1, 0]             # role_order(axis) — кэш, вычислимо
}
```

Чего в карточке НЕТ и быть не должно: records, hist, правила (выводимы),
что-либо про target-миры (карточка — только прожитый донор).

## 5. Шкаф — модуль `shelf.py`, API

```
Shelf.open(path)                    # загрузить или создать пустую
shelf.version                       # int, монотонный
shelf.cards                         # список карточек (только чтение)
shelf.add(card) -> int              # +карточка, версия+1, немедленный save
shelf.weights(), shelf.radius()     # калибровка/радиус ПО ТЕКУЩЕЙ полке,
                                    #   кэш инвалидируется на add
shelf.recognize(sig) -> Verdict     # правила v3: ближайшая карточка,
                                    #   d, radius, решение (ВВОЗ/нет карты/
                                    #   ОТКАЗ), + shelf.version в ответе
shelf.seed_archetypes()             # залить 4 архетипа repertoire.py
                                    #   (открыть их медленной дорогой,
                                    #   карточки как у всех)
```

Хранение: один JSON-файл `shelf/shelf.json` (карточек будут десятки —
каталог с файлом-на-карточку не нужен, решение пересмотреть после 500+).
При `add` — атомарная запись (tmp + rename).

Важно про пороги: `weights`/`radius` считаются заново при каждом изменении
полки — это сознательно (порог = свойство библиотеки). Пересчёт O(N²) по
десятку чисел — дёшево до тысяч карточек, НЕ оптимизировать заранее.

## 6. Раннер v4 — `exam_shelf.py` (новый файл, v3 не трогать)

То же, что v3, с тремя отличиями:

1. Репертуар узнавания = **шкаф** (не «4 архетипа + донор ad-hoc»).
   Донор экзамена открывается медленной дорогой (правило бюджетов v3:
   первый из 1000/1500/2000/3000 с осью) и кладётся карточкой на полку
   ДО узнавания цели.
2. Каждый вердикт печатается и пишется строкой в **ведомость**
   `exams_ledger.jsonl`: `{имя, вердикт, решение, d, radius, shelf_v,
   бюджеты, сиды, время}`. EXAMS.md остаётся человекочитаемым рассказом,
   JSONL — источник для подсчёта точности (цель этапа!).
3. Точностные счётчики: по накопленной ведомости печатать
   `ложные ввозы / ложные отказы / верные` (после вскрытия автором —
   поле «истина» дописывается в ведомость отдельной командой).

## 7. Петля пополнения (карантин карточки)

`ОТКАЗ` (новая форма) → медленная дорога → карточка-кандидат → **карантин**:

- ось принята судьёй (иначе кандидата нет);
- подпись стабильна: повторное открытие вторым сидом даёт
  `dist(sig1, sig2) <= radius` текущей полки (см. D2);
- только тогда `shelf.add`. Нестабильные — в `shelf/quarantine/` с причиной.

Плохая карточка портит узнавание всех будущих соседей — карантин дешевле
чистки полки.

## 10. Решения, которые надо принять (с рекомендациями)

- **D1. Линзовые подписи: хранить или вычислять?** Рекомендация: хранить
  (вычислены при открытии из сырых таймлайнов, как v3; из одних параметров
  оси точно не восстановишь — v3 это показал: рефит по зонду даёт слегка
  другой спектр). Цена — пара сотен байт на карточку.
- **D2. Критерий карантина.** Рекомендация: стабильность подписи по двум
  сидам (см. §7). Альтернатива «самоэкзамен донора» отвергнута: у донора
  нет экзамена в тройке.
- **D3. Радиус на тощей полке** (одинокая форма раздувает порог — hard2
  1.80, hard3 ввоз при 2.01). НЕ чинить константой. Рекомендация: пока
  карточек < 5, панель печатает предупреждение «полка тощая, радиус
  ненадёжен» — и всё; богатеющая полка лечит это сама.
