# WorldForge — харнесс слепого противника для held-out экзаменов

Не генератор «креативных миров». Генерация миров той же рукой, что владеет
ядром и прогнозом, — это подгонка (зелёные тесты даром). WorldForge
формализует то, что в серии 15.07 делалось руками с Grok (`EXAMS.md`):
внешняя модель порождает миры **вслепую**, а форж механически валидирует,
судит новизну и замораживает — прежде чем автор увидит содержимое.

## Петля

```
prompts/            человек задаёт СПЕК НОВИЗНЫ (про форму, НЕ про дыры ядра)
   │
   ▼
внешняя модель ──▶ тройки донор/цель ВСЛЕПУЮ (автор не читает содержимое)
   │
   ▼  harness.py
1. worldkit.Spec        компиляция — брак ловит компилятор (R1–R8)
2. triad.build          вывод target_probe (убрать действие-вопрос)
3. novelty_declared     гейт по ЗАЯВЛЕННОЙ структуре, БЕЗ запуска ядра
4. маршрут              novel → EXAM (frontier)   family → REGRESSION (CI)
5. манифест заморозки    git commit троек ДО прогона
   │
   ▼
прогон замороженным ядром (fastpath) → вердикт → ВСКРЫТИЕ только потом
```

## Разрыв круга (почему новизна судится ДВАЖДЫ и по-разному)

Соблазн: отбирать экзаменационных кандидатов метрикой `koopman.dist` —
«дальше радиуса, значит новая». Но узнаватель ядра судит **той же**
`koopman.dist`. Отбирая кандидатов метрикой ядра, гарантируешь, что ядро
назовёт их новыми — экзамен становится зеркалом фильтра, зелёное задаром.
Тот же грех, что «прогноз+код в одной руке», переодетый в метрику.

Развязка — две дистанции на **разных измерениях**:

| | измеряет | когда | чем |
|---|---|---|---|
| **гейт** (`novelty_declared`) | ЗАЯВЛЕННУЮ структуру из yaml: k, темп, направленность, кардинальность зонда | до заморозки, ядро НЕ бежит | грубо разделить frontier / регресс |
| **экзамен** (`fastpath`) | ВЫУЧЕННУЮ подпись: спектр оси, что ядро реально нашло | после заморозки | вынести вердикт |

Фильтр и вердикт независимы — круг разорван. Гейт даже уважает пределы ядра:
при k=2 не считает направленность (детальный баланс — направление
невыучиваемо, `sig.py:41`).

## Ретро-валидация против ведомости

`python3 worldforge/novelty_declared.py` — гейт классифицирует 7 троек серии
15.07 (которые он никогда не видел) по модели ядра (донор→репертуар→узнать
цель) и сверяет с `EXAMS.md`:

```
✓ comp1/comp2  семья       (узнана как донор)              → ВВОЗ  ✓
✓ comp3        отказ ввоза (цель k=4)                       → ОТКАЗ кардинальность
✓ comp4        отказ ввоза (цель темп 0.15)                 → ОТКАЗ спектр/темп
✓ hard1        провал открытия (k=4 > глубины 3)            → ПРОВАЛ открытия
✓ hard3        провал открытия (кольцо, топология вне реп.) → ПРОВАЛ открытия
~ hard2        отказ ввоза (консервативно, см. ниже)        → ждали ВВОЗ
```

**6/7, и причины дословно совпадают с ведомостью** — гейт воспроизвёл сам
механизм каждого вердикта, ничего не запуская.

`hard2` — единственное расхождение, задокументировано честно: цель ближе
всего к своему донору (метрика верно ранжирует её как почти-семью), но
возмущение темпа 25→22 (Δ=0.03) × вес темпа 24 = 0.72 превышает радиус 0.48,
который задаёт тощая библиотека из 4 близнецов. Промах в **безопасную**
сторону (регресс→экзамен, не наоборот). Веса под 7/7 не крутим — это была
бы подгонка под ведомость. Богаче библиотека — уйдёт сам.

## Станок (front-end генерации)

`mill.py` — станок: оператор крутит ручки, станок печатает валидные тройки
через OpenRouter. `client.py` — клиент OpenRouter на stdlib (ноль зависимостей).

**Слепота сохранена ручкой панели.** Станок пишет миры в каталог, но на экран
выводит ТОЛЬКО ФОРМУ (k, темп, топология, маршрут гейта) — не слова. Оператор
крутит ручки, глядя на распределение форм, содержимого не читает.

```
OPENROUTER_API_KEY=sk-or-...   # добавь в .env (обязательно)
OPENROUTER_MODEL=x-ai/grok-3-mini   # опц., модель по умолчанию

python3 worldforge/mill.py --models                    # памятка моделей
python3 worldforge/mill.py --n 8 --model x-ai/grok-3-mini --temp 1.0
```

Ручки: `--n` (сколько годных троек), `--model` (какая чужеродная модель бьёт
в стыки), `--temp` (разброс), `--out`. Акценты формы станок ротирует сам
(лестница/тумблер/кольцо/сток/глубина/резкость) — покрыть пространство форм,
не штампуя одну.

## Файлы

- `client.py` — клиент OpenRouter (stdlib urllib, креды из `.env`).
- `mill.py` — станок: ручки → генерация → валидация → панель формы → каталог.
- `novelty_declared.py` — подпись из `Spec`, дистанция, порог, `classify_triad`;
  `__main__` = ретро-тест против `EXAMS.md`.
- `triad.py` — вывод `target_probe`, валидация тройки; `__main__` = само-тест
  регенерации (7/7).
- `harness.py` — оркестровка приём→маршрут→манифест.
- `prompts/grammar.txt` — грамматика мира для внешней модели.
- `prompts/novelty_spec.txt` — слепой спек новизны (про форму, не про дыры).

## Использование (полный цикл)

```
# 1. СТАНОК печатает тройки вслепую (содержимое НЕ читай):
python3 worldforge/mill.py --n 8 --model x-ai/grok-3-mini --out worldforge/in
# 2. Маршрутизация + манифест заморозки:
python3 worldforge/harness.py worldforge/in --out worldforge/out
# 3. Заморозь frontier коммитом (команда в манифесте), потом прогон ядром,
#    вердикт, и ТОЛЬКО ПОТОМ вскрытие содержимого.
```

Границы: гейт судит форму, а не смысл. Он не заменяет экзамен — он решает,
какие тройки достойны экзамена, а какие лишь регресс. Слепоту (не читать до
вердикта) соблюдает оператор; форж делает соблюдение дешёвым.
