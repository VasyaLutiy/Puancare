# DevOps-агент v1 — PDDL-планировщик + саморемонт модели из провалов

## Context

Итог спора (фундамент проекта): строим **не аналог LLM** и **не конкурента Terraform**.
Terraform — «руки» (детерминированно исполняет написанный человеком план), Claude —
stateless-генералист (умный, но стохастичный, дорогой на каждый вызов, без памяти о
КОНКРЕТНОЙ среде). Пустой угол между ними — **автономный «мозг-SRE»**: Monitor → Analyze →
Plan + **саморемонт модели мира из провалов**. Это единственная подлинная новизна над всем
полем (GDA / model-lite planning / action-model learning), и именно её v1 обязан показать на
одном «щелчке».

Ключевой принцип из спора: **планировщик = движок решения (PDDL+pyperplan/Fast Downward),
обучение = ремонт ДОМЕНА (action-model), а не политики.** Детерминизм мира ≠ известность
модели: мир детерминирован, но порог OOM неизвестен, пока не запустишь → его надо выучить
интервенцией. Полный замысел — в `ResearchDevops.md`.

## Решения (зафиксированы с пользователем)

- **Объём v1:** хребет + cost-gated **LLM-оракул**. Мета-домен (эпистемическое планирование
  экспериментов) — НЕ в v1, отложен в v2.
- **Первая задача-мир:** память / OOM (чистейший plan-execution-gap).
- **Метрики:** триангуляция (см. ниже), НЕ «токены-vs-Клод» в одиночку.

## Стек (по факту разведки)

- **Планировщик:** `unified-planning` + `up-pyperplan` (pure-Python, безопасно на VPS
  Python 3.14; без C++-wheel рисков). `up-fast-downward` — апгрейд на потом.
- **Мир:** **Docker** на VPS (`docker run --memory=<bucket>`); k8s нет и не нужен для MVP.
  OOM детерминирован (`docker inspect` → `State.OOMKilled`, ExitCode 137).
- **Числа → бакеты:** память дискретизируем (64/128/256/512/1024 MiB) → пропозициональный
  домен, pyperplan работает, обучение находит безопасный бакет.
- **LLM-оракул:** переиспользуем `utils_azure.AzureJSON`; **инструментируем `resp.usage`**
  для подсчёта токенов (его сейчас нет).
- **Среда:** venv на VPS (Python 3.14; fallback 3.12 если `up-pyperplan` не встанет).

## Архитектура и файлы (новый подпроект `devops_agent/`)

- **`world.py`** — песочница-Gym. `World.apply(spec) -> Obs`. spec=`{service,image,mem_bucket}`.
  `docker run --memory=<bucket>` → `docker inspect` → `Obs{phase, exit_code, oom_killed}`.
  Детерминированно, чистит контейнер. Восприятие = парсинг структуры, без NLP.
- **`services.py`** — 2–3 синтетических сервиса с ИЗВЕСТНЫМ нам (не агенту) футпринтом +
  **наблюдаемая фича** в spec (`workload_class`/`image`), над которой обобщаются правила.
  `svc_a` ~300MiB (OOM <512), `svc_b` лёгкий ~100MiB (контрпример), `svc_c` тяжёлый ~700MiB.
- **`bios.py`** — BIOS-state как **читаемые редактируемые данные**: предикаты + схемы действий
  (`set-mem`, `deploy`) + **выученные правила** (`unsafe-mem(feature,bucket)`).
  `compile_to_up()` собирает `unified_planning.Problem`. Агент правит данные → перекомпилирует
  → перепланирует. «Домен = BIOS, обучение = правка домена» — буквально.
- **`agent.py`** — петля + **обратный индекс (интуиция)** `симптом→ранжированные причины`:
  `plan` → `predict` → `act` → `compare` → при gap: `localize` интервенцией (бинарный поиск по
  бакетам) → `learn` (правило в forward-карту + бамп reverse-индекса) → `replan`.
- **`oracle.py`** — `AzureJSON`-обёртка, **cost-gated** (вызов только когда reverse-индекс
  плоский) + учёт токенов (`resp.usage`).
- **`metrics.py` + `run_experiment.py`** — харнесс: лог per-episode (trials-to-converge,
  LLM-queries, исход); baseline-раннеры (LLM на ту же задачу + замер дисперсии команд).

## Порядок коммитов (M0–M7)

- **M0 — Мир.** `world.py` + `services.py`. Детерминизм: один spec → один Obs.
  `svc_a` падает в OOM при <512 и живёт при ≥512 (ground-truth).
- **M1 — BIOS + планировщик.** наивный домен (`deploy → running` всегда) + `compile_to_up` +
  `up-pyperplan` выдаёт план `[set-mem default, deploy]`.
- **M2 — Хребет петли.** predict `running` → act → детект **execution-gap** (OOM) на `svc_a`.
- **M3 — Рождение правила (первый щелчок).** Интервенция: бинарный поиск по бакетам → флип →
  правило `unsafe-mem(svc_a, <512)` в BIOS-state → replan → `running`.
- **M4 — Интуиция.** reverse-индекс `OOM→memory_limit`; повторный `svc_a`: predict+fix
  превентивно, без повторного открытия (trials → ~0).
- **M5 — Перенос + контрпример.** `svc_c` (тяжёлый, та же фича) — правило переносится;
  `svc_b` (лёгкий) — контрпример **карвит** область. Обобщение И специализация.
- **M6 — LLM-оракул + токены.** Новый симптом (health-check fail), индекс плоский → оракул
  **один раз** → запись → дальше 0. Амортизация и сжатие фронтира.
- **M7 — Триангуляция.** Харнесс строит кривые и сравнивает.

## Метрики (триангуляция — главное)

1. **trials-to-converge** на эпизод (падает).
2. **Перенос:** проб на НОВОМ сервисе той же фичи (→ ~0).
3. **LLM-query curve:** обращения к оракулу **падают** (главный критерий).
4. **Детерминизм/дисперсия:** агент даёт тот же план (дисперсия 0); LLM-baseline — разброс
   команд на повторах.
5. **Человеко-правок сэкономлено** vs статичный Terraform (агент 0, Terraform требует правки).

Токены-vs-LLM — **вторичная** метрика, на объёме повторов.

## КРИТЕРИЙ УБИЙСТВА (дисциплина фальсификации)

- Если **trials не падает** ИЛИ **перенос не работает** ИЛИ **LLM-кривая не снижается** →
  модель не учится → **хороним честно**.
- Бить бейзлайны: (a) случайный перебор бакетов; (b) «всегда спрашивать LLM»; (c) статичный
  плейбук без обучения.
- Судья — **песочница (Docker), не мнение LLM**. Однопеременная интервенция против ложной
  каузальности.

## Переиспользуем из Puancare

- `utils_azure.AzureJSON` → оракул (+ инструментовка `resp.usage`).
- Дисциплина эксперимента/харнесса из `step3*`/`stepB*`.
- (Опц.) словарь атомов как идея для фич-вокабуляра spec.
- **НЕ берём:** `h_ic`/WordNet-дерево, TDA, строгое «is-a = вложение».

## Верификация (end-to-end на VPS)

Поток: код локально → push → на VPS `git pull` → боевой прогон.
1. venv: `pip install unified-planning up-pyperplan pddl` (3.14; иначе 3.12). Smoke: pyperplan
   решает наивный домен.
2. `python world.py --selftest` → детерминизм Obs, OOM-порог `svc_a` = ground-truth.
3. `python run_experiment.py` → M2 gap; M3 рождение правила → `running`; M4 второй `svc_a` 0
   интервенций; M5 перенос на `svc_c` + карвинг на `svc_b`; M6 один вызов оракула, потом 0.
4. Харнесс печатает 5 метрик + кривые → trials и LLM-queries **падают**.

## Честные риски

- **Бакеты вместо чисел** — упрощение (numeric ENHSP в v2).
- **Docker ≠ k8s**, одна машина, синтетический футпринт — узкая лаборатория.
- **Обобщение над фичей** честно только если фича наблюдаема в spec; «правильный уровень
  обобщения» — открытый вопрос (v1: скоп по фиче + карвинг контрпримером).
- **pyperplan слаб** для больших доменов → Fast Downward/ENHSP в v2.
- **Мета-домен отложен** — в v1 интервенция захардкожена (бинарный поиск по одному параметру).
