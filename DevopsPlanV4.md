# v4 — Knowledge Graph: знание = граф, PDDL = упаковщик/ground-truth

## Context

v3 доказал (минимальная проверка гипотезы, §8 ЖИВ): механизм `propose→verify→amortize`
выращивает PDDL-схему из провалов. Но знание там жило в плоском in-memory реестре
(`MetaBios`) и умирало с процессом. Архитектурный сдвиг (память `devops-agent-architecture-direction`):

- **знание = ГРАФ** (KG), не PDDL;
- **6 мета-типов = ISA агента** (Entity, Resource, Setting, Status, Intervention, Dependency) — фиксированный контракт;
- **PDDL meta-domain = упаковщик-ground-truth**: что не проецируется в валидный PDDL по 6 типам — не входит в граф;
- идентичность вещи = её **структурная сигнатура** (тип+рёбра+интервенции); смысла у агента нет, только структура.

## v4-M1 — Knowledge Packer + типизированный граф (PDDL = ground-truth gate)

Максимально абстрактный, **контент-нейтральный** компонент: фрагмент знания (от LLM/интроспекции/пробы/теста)
→ упаковка в KG как корректно-типизированные узлы/рёбра → валидация. Покрывается большой батареей situation-тестов.

**Форки (согласованы):**
1. Граф — лёгкий: dataclasses + dict-узлы + список рёбер + JSON. Без graph-БД (тестируем гипотезу, не инфраструктуру). `cat`-абельно = аудируемо.
2. v4 **поглощает** v3: flat-реестр `MetaBios` станет частным случаем KG; `mint_dimension`/`domain_gen` переезжают на граф (рефактор — после кейстоуна).

**Ground-truth — два слоя:**
- структурный контракт (`contract.py`): инварианты 6 типов + легальные рёбра;
- PDDL-проекция (`projection.py`): KG→PDDL + FD парсит/решает. *Упаковка корректна ⟺ граф round-trip’ится в решаемый PDDL.* Движок `solve` переиспользуем из v3.

## Раскладка

```
devops_agent/v4/
  graph.py        # KnowledgeGraph: MetaType/Rel/Node/Edge + dict-узлы + JSON save/load
  contract.py     # validate(g) → нарушения (структурный слой ground-truth, контент-нейтрально)
  projection.py   # kg_to_pddl + solve (PDDL-слой ground-truth); + keystone selftest
  packer.py       # (след. шаг) фрагмент → validate → commit|reject; поглощает mint_dimension
```

## Порядок (кейстоун-первый)

- **Кейстоун-1 (этот заход):** граф+контракт+проекция; selftest на ВЫМЫШЛЕННЫХ не-devops графах (database, queue) → валидация → KG→PDDL → FD решает. Доказывает контент-нейтральность. Одна сущность; lifted-actions.
- **Кейстоун-2:** мульти-сущность + Dependency (ground-actions / `:constants`) — где планировщик начинает делать реальную работу (мост к «оси B»).
- **Packer + батарея:** фрагмент→граф, идемпотентность/дедуп, композиция, персистентность, отказы малформов; + анти-хардкод (новые вымышленные домены без правок логики).

## DoD кейстоуна-1

Вымышленные графы (db/queue) валидны и решаются FD; контракт ловит малформ (висячий ресурс,
интервенция без эффекта, нелегальное ребро); persistence round-trip; в проекции нет `:metric` (#8);
ZERO devops-хардкода в graph/contract/projection (memory/config — просто ещё одна situation).

## Критерий убийства

Если новый вымышленный домен требует правок логики (не только данных графа) — печатаем «не обобщается»,
это часть вердикта, не маскируем. Судья проекции — FD, не мнение.
