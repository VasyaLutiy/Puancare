# WORLD_PROTOCOL.md — контракт между конструктором миров и организмом

Владелец этого файла: сессия-организм. Владелец datalite/worldkit: ветка.
Ветка пишет ТОЛЬКО новые файлы (datalite.py, worldkit.py, blueprints/...),
не трогает organism.py / memory.py / exp*.py. Проверка соответствия —
`python3 conformance.py <модуль_мира>` (см. ниже), без участия организма-
сессии: мир #4 остаётся held-out.

## 1. Объект-мир (то, что порождает worldkit)

Обязательные методы:

- `observe() -> dict`
  Форма: `{коллекция: {имя_объекта: {атрибут: значение, ...}, ...}, ...}`
  Имена коллекций/атрибутов/значений — непрозрачные строки (язык любой).
  СКРЫТЫЕ атрибуты в observe() НЕ попадают никогда (аксиома интерфейса).

- `action_space() -> list[(действие: str, цель: str|None, kwargs: dict)]`
  Только валидные в текущем состоянии действия (исчезнувшие объекты
  не перечисляются).

- `step(действие, цель=None, **kwargs) -> transition`
  transition = {
    "obs":       observe() ДО действия,
    "action":    str, "target": str|None, "args": dict,
    "result":    str,          # стабильная строка (A5: один смысл — одна строка)
    "effects":   list[tuple],  # ("вид_эффекта", "имя_затронутого", ...)
    "obs_after": observe() ПОСЛЕ,
  }

- Детерминизм: одинаковый seed => побайтово одинаковый мир и динамика.

## 2. Клей (worldkit обязан вывести его из blueprint автоматически)

GLUE = dict(
  object_actions = (...),   # действия, образующие сигнатуры объектов
  ctx_fn(obs, a, t, kw) -> frozenset((атрибут, значение)),  # видимое цели
  entities_fn(obs) -> {имя_сущности: состояние},            # для абдукции связей
  truth_fn(w, t) -> str|None,          # скрытая истина (ТОЛЬКО диагностика)
  factory(ep) -> мир,                  # ep = номер эпизода, seed = base+ep
  link_truth(ep, объект, сущность) -> bool,   # истина связей (диагностика)
)
EXAMS = [(метка, действие-зонд, действие-вопрос, нужен_ли_откат_зонда), ...]

## 3. Требования к динамике (иначе мир невыучиваем текущим ядром)

- R1. Исход действия определяется конъюнкцией <= 2 предикатов
      (включая изобретённые class*/linked_live). Тройные условия
      текущий майнер не выражает (MAX_CONDS=2).
- R2. Каждая скрытая переменная представлена >= 2 значениями в каждом
      мире (иначе невыводима) и наблюдаема через >= 2 разных действия
      (иначе экзамен зонд->вопрос невозможен).
- R3. Каскад = эффект ("вид", имя_сущности), где имя присутствует в
      entities_fn(obs) того же шага, и сущность была в "живом" состоянии.
      Так работает реляционная абдукция; иные формы связей она не увидит.
- R4. Хотя бы один носитель каскада должен быть досягаем для действий
      агента (урок exp0: root-конфиги делали связь непознаваемой).
- R5. Должно существовать действие-вмешательство (create/buy/купить),
      разрушающее корреляции-ловушки, иначе суеверия вечны (урок exp1).
- R6. Строки result/effects стабильны и взаимно-однозначны причинам (A5).
- R7. Масштаб под текущие бюджеты: ~8 объектов, 2-3 сущности,
      2-6 значений на атрибут. Бюджеты прогонов: 300 и 2000 шагов.
- R8. Мутация скрытого (фаза 2) — разрешена грамматикой, но помечается
      флагом в blueprint: организм её пока не переживает, это план.

## 4. Формат клаузы datalite (ЖЁСТКО, ради будущего дифа теорий)

Правило = (действие: str, условия: frozenset[(атрибут, значение)], исход)
исход = (result: str, tuple(отсортированных видов эффектов))

Это в точности формат правил в памяти агента (memory.py). Совпадение
форматов делает метрику "выучил ли агент замысел автора" операцией
сравнения множеств с точностью до переименования изобретённых предикатов.

## 5. Семантика исполнения

- Первое совпавшее правило (decision list), НЕ монотонный вывод:
  правила упорядочены, специфичные раньше общих.
- Эффекты — императивные правки состояния (удалить объект, сменить
  состояние сущности, создать объект), исполняются движком после
  выбора правила. Datalog отвечает "что произойдёт", эффекты — "что изменить".
