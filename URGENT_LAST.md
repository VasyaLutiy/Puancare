## Баг в 2000-curious: СУТЬ ПРОБЛЕМЫ

### Что происходит

У 2000-curious организма классы **расщепляются**:
- `class0` ← симптомы `['использовать']`
- `class1` ← симптомы `['проверить']`

Экзамен требует: знаешь результат зонда `проверить` → предскажи результат `использовать`. Но если они в разных классах — это невозможно.

### Корень проблемы — ТАВТОЛОГИЧЕСКИЕ КЛАССЫ

**Сплит-классы тавтологически идеальны:**
- `class0` для `использовать` = кластер определяется из **результата самого `использовать`** → 0 плохих предсказаний
- `class1` для `проверить` = кластер определяется из **результата самого `проверить`** → 0 плохих предсказаний

**Объединённый класс всегда несовершенен:** из-за деградации батареек между зондом и использованием появляются противоречивые пары (ток_есть, не_работает). Это создаёт плохие предсказания → MDL **всегда предпочитает сплит**, никакой `CLASS_PENALTY` не помогает.

### Конкретные числа (после 2000 шагов)

```python
_dyn: True
objects with BOTH probe+ask: 19
pair distribution: Counter({('ток_есть', 'работает'): 12, ('ток_нет', 'не_работает'): 5, ('ток_есть', 'не_работает'): 2})
consistent: 17/19 = 89%
```

89% консистентности — функциональная проверка проходит (65% порог). Но MDL отвергает слияние потому что:

```
DL_split   = rules_cost + 0×EP_COST + 2×CLASS_PENALTY = X + 20  (0 плохих!)
DL_merged  = rules_cost + 23×EP_COST + 1×CLASS_PENALTY = X + 102 (23 плохих от деградации!)
```

### Направление исправления (не реализовано)

**Действие-специфичное присвоение класса при relabeling:**

При переразметке исторических записей (в `_relabel()`), если действие входит в группу класса, определять значение класса **только из собственного результата этого действия**, а не из всех действий группы:

```python
# При relabeling записи action=A:
# - если A ∈ группа класса → класс определяется из sig[obj][A]
# - если A ∉ группа класса → класс определяется мультидействийно (текущее поведение)
```

Тогда:
- Запись `проверить` → класс из probe result → 0 плохих ✓
- Запись `использовать` → класс из use result → 0 плохих ✓  
- Но правила будут разными кластерами для probe vs use → а это нормально!

На экзамене: `infer(probe_action, probe_result)` даёт `(class0, c1)` → ctx + `(class0, c1)` → правила `использовать` c1 → правильное предсказание.

Это разрывает тавтологию и позволяет MDL выбрать объединённый класс.
