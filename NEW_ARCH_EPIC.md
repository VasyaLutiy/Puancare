## 0. Диагноз (запах реальный, лекарство — нет)

Кирилл заметил: пора «переписать нормально — микросервисы, единая шина данных,
интерфейсы, строго отделённое ядро-математика, зафиксированные контракты и
структуры данных».

**Запах верен.** Симптомы архитектурного долга, наблюдаемые прямо сейчас:
- `chest.py` лезет в приватные потроха: `org.hist`, `org.axes`, зовёт
  `org._relabel` (метод с подчёркиванием). Контракта персистентности нет.
- `sig.py` лезет в `ax.emis_p`, `ax.T()`, `ax.res_a`, `ax.pi`. Контракта
  подписи нет.
- `runworld.Organism = Organism` — обезьяний патч вместо интерфейса ядра.
- `record` — словарь со строковыми ключами (`"obj"/"ctx"/"outcome"/…`),
  `ctx` = `frozenset` кортежей, `outcome` = голый кортеж, `obj` = `(ep,name)`.
  Структуры данных на границах — неявные и стрингово-типизированные.

Налог: каждый новый компонент (chest, sig, скоро recognition) сначала
обратно-инженерит чужую неявную структуру.

## 1. Лекарство — НЕ микросервисы

Микросервисы решают деплой / масштаб / команду: независимый выкат, разные
языки, изоляция сбоев, размазка по машинам, много разработчиков. У проекта
НИ ОДНОЙ из этих проблем: один исследователь, одна машина, один язык, цикл в
секунды-минуты, горячие петли (EM, сон, belief по-объектно). Сетевая шина =
сериализация и задержка на КАЖДЫЙ шаг = катастрофа скорости за ноль пользы.

Правильная ось «правильности» здесь — **модульность с контрактами внутри
одного процесса**. Всё, что хотел Кирилл (отдельное ядро, фиксированные
контракты, явные структуры), даётся так — без распределённого налога.

## 2. Целевая карта модулей (звезда)

```
   МИР        контракт: observe/step/action_space   (уже есть: WORLD_PROTOCOL.md)
    │  типы: Наблюдение, Переход
    ▼
   ОРГАНИЗМ (тонкая петля act/sleep/infer)
    ├─ ПАМЯТЬ/BELIEF          типы: Эпизод, Belief
    ├─ УЧЕНИК (EM, оси)  ───► типы: Ось/Шаблон
    ├─ СУДЬЯ (биты, MDL) ◄─── ЯДРО-МАТЕМАТИКА: ни одного слова о мире
    └─ ДРАЙВ (любопытство)     (= правило слепоты + MODEL.md; ядро обязано быть слепым)
    │  типы: Эпизод, Ось
    ▼
   СУНДУК (персистентность)   контракт: схема chest (JSON, теговый кодек)
    ▼
   УЗНАВАНИЕ (следующий шаг)  типы: Подпись, Библиотека шаблонов
```

- **«Шина данных»** в нашем масштабе = поток эпизодов (`records`), он уже
  концептуально шина. НЕ брокер сообщений.
- **«Интерфейсы»** = сигнатуры функций + типизированные структуры на границах.
  НЕ сетевые вызовы.
- **Ядро-математика** (судья/HMM/belief) — запечатанный кернел без знания о
  мире. Это философски обязательно (правило слепоты), не просто аккуратно.

## 3. Что фиксировать в контракт — и КОГДА

Правило: **контракт пишется ПОСЛЕ понимания, не до** (MODEL.md родился после
E-серии). Фиксируем только границы (а) устоявшиеся и (б) которые вот-вот
пересечём.

Зрелые к фиксации:
- **WORLD_PROTOCOL** — уже контракт мира, оставить как есть.
- **Схема сундука** — только что стабилизировалась (chest.py). Можно поднять
  до явного контракта персистентности.

Фиксировать прямо перед их пересечением:
- **Подпись + Шаблон** — перед recognition (весь recognition про сравнение
  этих структур между мирами).

Держать ТЕКУЧИМИ (не бетонировать):
- внутреннее представление судьи (Оккам/Риччи/розетка ещё в движении);
- представление шаблона (recognition ещё покажет его форму);
- `Axis` — за неделю оброс `pi`, `pen_dyn`; recognition добавит поля
  абстракции. Заморозить сейчас = ломать через ход.

## 4. Конкретные структуры данных (кандидаты в контракты, когда созреют)

- `Наблюдение` = {коллекция: {объект: {атрибут: значение}}}
- `Переход` = обёртка step() (obs, action, target, args, result, effects,
  obs_after) — уже полу-контракт в WORLD_PROTOCOL §1.
- `Эпизод` = (ctx: набор предикатов, action, outcome) — сейчас голый кортеж,
  кандидат в dataclass со схемой.
- `Ось/Шаблон` = (k, эмиссии, hazard, tgt, pi, направленность…) — dataclass.
- `Подпись` = мир-агностичный вектор формы (k, устойчивость, направленность,
  резкости, исходы) — см. sig.py, метрика направленности ещё сырая (при k=2
  тождественно 0, это мат-факт — чинить через асимметрию hazard).
- `Сундук` = снимок одной жизни (hist, records, оси, R, problem_actions,
  steps); правила выводимы, не хранятся.

## 5. ЗАПРЕТ (главное)

**Big-bang rewrite «сейчас всё перепишем нормально» — ловушка.** Он ощущается
продуктивным, полностью tractable, и может съесть недели, не ответив ни на один
исследовательский вопрос. Это зелёный тест в архитектурной обёртке — ровно та
гравитация Клода к доступному, которую Кирилл ловит. Ядро только что заморожено
(organism2). Переписывать до recognition = бетонировать текущие структуры.

Двигаться ТОЛЬКО инкрементально: упрочнять по одной устоявшейся границе за раз,
когда её всё равно пересекаем. Эта звезда — ориентир, не спринт.

## 6. Порядок (когда дойдут руки, не раньше recognition)

1. Поднять схему сундука до явного контракта (дёшево, граница зрелая).
2. Перед recognition — зафиксировать `Подпись` и `Шаблон` как типы; починить
   метрику направленности (асимметрия hazard вместо потока при стационаре).
3. Ввести тонкий интерфейс ядра (убрать `runworld.Organism = ...` патч).
4. Перевести `record`/`ctx`/`outcome` из голых dict/tuple в dataclass со
   схемой — но только когда их форма перестанет плыть.
5. Ядро-математику отделить в модуль без импорта мира (закрепить слепоту кодом,
   а не обещанием).
